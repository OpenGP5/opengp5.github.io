Hardware

Memory, pins and clocks of both chips.

These notes come from a GP-5 with main board GP-5_MB_V01_241115. Use platform/nds32/ for the control chip’s register code and platform/dsp/ for the sound chip’s code. Check your board against this one before using its pin map.

The DSP is the digital signal processor for sound. The control processor runs the screen, controls, USB and storage. It can also process sound. RAM holds working data; flash keeps code and saved data when power is off.

Control processor: MVsilicon BP1048B2 (Andes NDS32 V3, D1088 core)

Clocks

A phase-locked loop (PLL) multiplies the crystal clock to make the faster clocks used by the chip.

Clock or settingValue
Crystal24 MHz
Main PLL and system clock288 MHz by default; 320 MHz with "control": {"mhz": 320}

Core regulator at 320 MHz1.25 V, matching Valeton’s firmware

The manifest has supported 320 MHz since platform 0.6.0. The efuse holds the chip’s factory trim values.

Flash and RAM

The board has 2 MB of SPI flash, JEDEC ID 85 60 15, with no write-protected blocks. SPI is the serial bus used to reach the flash chip. JEDEC ID identifies that chip.

Range or addressContents
0x0–0xFFFFFactory loader; USB update tools cannot overwrite it
0x10000App start, section 0x62; accepts up to 1,440 KB
0x13E168End of Valeton’s V1.0.6 app
0x13F000–0x189FFFThe installed build’s shared storage area
0x160000–0x161FFFSettings store, gp5_store_*, in two 4 KB sectors
0x170000Valeton’s 100-byte preset-order table
0x171000–0x189FFFWorking user-preset store when Valeton’s firmware runs
0x190000Valeton factory presets, section 0x65
0x20000000–0x20047FFFRAM
0x20003000–0x20004000App stack
0x20004000Start of app data and bss; see platform/nds32/start/app.ld

An app update erases the range it writes. The flash ranges above were checked with gp5_link.py flash-read. See Storage for the rules that keep file writes within the shared area.

Interrupts and pins

An interrupt lets the chip handle an event before returning to the main code.

LineSourceTask
0Timer 11 ms tick
7UART0DSP link
8Timer 2LEDs

UART is the serial link between the two chips. Pin names below match the chip’s port names. A low signal means ground level; a high signal means the pin’s logic-high level.

PinUse
A0 / A1UART0 receive / transmit to the DSP
A7 / A9 / A16Screen data/command, chip select and reset; SPI master port 0 sends data
A10Screen backlight, timer 5 pulse-width modulation (PWM)
A17Foot switch; low when pressed
A28Volume knob, analog-to-digital converter (ADC) channel 9
A29 / A30 / A31Blue / red / green for all three LEDs; high means on
B2 / B3PARA quadrature encoder; both high at a detent
B6PARA press; low when pressed
A15, A22, A24, B5Board outputs; board_init in main.c drives them as Valeton’s app does

The screen is 160 × 80 colour pixels with an ST7735S-type SPI controller. USB uses full-speed device mode. The open firmware polls USB and shows the MIDI port and audio device name OpenGP5 (before 1.0: GP-5 Open FW).

The 48 kHz clock value is the second entry in Valeton’s DSP clock table. See platform/dsp/gp5_dsp.h for the memory your effect can use and the memory reserved for the platform. The extra float unit was no faster than the M4 in these tests, so the platform does not use it.

Debug header J7

J7 provides Serial Wire Debug (SWD). The triangle marks pin 1.

PinSignal
1Ground
2Reset
3SWCLK
4SWDIO
5SWO

For the confirmed DSP update fault, follow J7 recovery.
