Parameters and presets

Define settings, choose save flags, and use them in presets and Launchpad.

Declare your firmware’s settings in params.h. The platform uses that list to:

  • send DSP-marked values when they change and after a DSP restart;
  • keep values marked SAVE or PRESET across power-off;
  • keep named presets if the manifest defines slots;
  • let a computer read and change values.

Launchpad uses the list to build its Live editor. Parameter support began in platform 0.7, with the 1.0 API.

Your control code can read and set these values. The UI kit supplies a settings page that lets users select and edit them with PARA.

Declaring them

params.h, at the top of the firmware’s folder (next to firmware.json):

#define GP5_PARAMS(P, C)                                                                                     \
    P(RATE,  "Rate",  "Tremolo", 50, 1500, 500, GP5_U_CUSTOM,  GP5_P_DSP | GP5_P_PRESET)  /* 1/100 Hz */      \
    P(DEPTH, "Depth", "Tremolo", 0, 100, 50, GP5_U_PERCENT,     GP5_P_DSP | GP5_P_PRESET)                    \
    C(SHAPE, "Shape", "Tremolo", 3, "Sine|Triangle|Square", 0,  GP5_P_DSP | GP5_P_PRESET)                    \
    C(ON,    "Effect", "Tremolo", 2, "Off|On", 1,               GP5_P_DSP)

P(id, name, group, min, max, default, unit, flags)     a number, min..max, within -32768..32767
C(id, name, group, count, "A|B|C", default, flags)     a choice, 0..count-1

Each line gives an id, GP5_P_RATE, GP5_P_DEPTH and so on (0, 1, 2 …, in order), and GP5_NPARAMS counts them. Names and groups have at most 15 characters; a choice list at most 47. Launchpad shows each group as a card.

Values are whole numbers from -32,768 to 32,767, kept as 2 bytes in saved settings and presets; this range is fixed for all of 1.x. Pick the step the user needs and say it in the unit: 1/100 Hz for a rate, ms for a time, tenths of a dB for a gain. Something that needs more (a length in samples, say) is better stored in a coarser unit, or as two parameters.

Units

How a computer shows a value:

unitshown as
GP5_U_NONEthe number
GP5_U_PERCENT50 %
GP5_U_DB10tenths of a dB: -60 → −6 dB
GP5_U_MS350 ms, 1.5 s
GP5_U_HZ440 Hz
GP5_U_SEMITONES+7 st
GP5_U_CENTS10tenths of a cent
GP5_U_CUSTOMyour own text: fw_param_text() on the control chip writes it (below)

Flags

FlagEffect
GP5_P_DSPthe DSP gets it: fw_param(id, value) there, and gp5_param(id)
GP5_P_PRESETpart of a preset; also kept across power-off as part of the current sound
GP5_P_SAVEkept across power-off on its own: a global setting, not part of presets
GP5_P_READONLYthe computer may read it, not set it: a state such as “looping” or the note played
GP5_P_HIDDENnot shown in Launchpad’s editor

A parameter with neither PRESET nor SAVE starts at its default after every power-on (the tremolo’s ON).

Control processor

#include "gp5_params.h"

void fw_para_turn(int d) { gp5_param_set(GP5_P_DEPTH, gp5_param(GP5_P_DEPTH) + 5 * d); }
void fw_foot_down(void)  { gp5_param_set(GP5_P_ON, !gp5_param(GP5_P_ON)); }
  • gp5_param(id): the current value. By fw_init() the saved values are already in place.
  • gp5_param_set(id, value) sets a value from your control code. It clamps the value to its range and sends it to the DSP if marked GP5_P_DSP. For SAVE or PRESET values, it schedules a save two seconds after the last change. It returns 1 if the value changed. The delay reduces flash writes while the user turns a knob.
  • fw_param_changed(id) (optional): a value changed from outside, either from the computer or from a preset load (once per parameter that changed). Redraw, or update the LEDs. It is not called for your own gp5_param_set.
  • fw_param_text(id, value, text) (optional): for GP5_U_CUSTOM, write up to 15 characters and return 1. The computer asks for it (USB 7E 15), so your screen and Launchpad show the same thing:
int fw_param_text(unsigned id, int32_t v, char *t)    /* RATE: 500 -> "5.00 Hz" */
{
    if (id != GP5_P_RATE) return 0;
    ...
    return 1;
}

DSP

static void fw_param(uint32_t id, int32_t value)
{
    if (id == GP5_P_RATE) step = (float)value / 100.0f / (float)GP5_SAMPLE_RATE;
}

The platform keeps every DSP parameter’s value; gp5_param(id) reads it anywhere, including in fw_process. The platform calls fw_param before the next audio block. Use it to compute filter coefficients, delay lengths or other values that need extra work. Read small values where you use them. The DSP starts with defaults from params.h until the control chip sends the saved values.

Link command 0x7F10 carries parameters; a firmware’s own link commands start at 0x7F11.

Presets

"presets": N in firmware.json (up to 64). A preset holds every GP5_P_PRESET parameter and a name of up to 12 characters.

CallResult or action
gp5_preset_count()N
gp5_preset_load(n)0 if preset n is empty (nothing changes); otherwise every value, then fw_param_changed for each one that changed
gp5_preset_save(n)the current sound into n, keeping its name
gp5_preset_current()the preset loaded last, -1 if none
gp5_preset_dirty()1 once the sound differs from that preset (show a *)
gp5_preset_used(n)Check whether slot n holds a saved sound
gp5_preset_name(n)Read slot n’s name
gp5_preset_rename(n, name)Change slot n’s saved name

The platform saves the current preset number with the current sound. Your firmware chooses the controls: the tremolo loads on the PRESET row and saves on a PARA hold. Launchpad can load, save and rename presets through the same API. Changing the current sound does not overwrite a saved preset until you call gp5_preset_save(n).

How they are stored

In the firmware’s own storage (storage.md), as store records whose ids come from the firmware’s id: one for the current sound, one for each preset. A record keeps pairs of (a hash of the parameter’s name, value), not positions, so an update that adds, removes or reorders parameters keeps what was saved:

  • a new parameter starts at its default;
  • a removed one is dropped;
  • a renamed one starts at its default (keep names once released).

Ranges are applied when values are loaded.

Launchpad includes these records in a backup. Restoring them returns the saved presets and current sound. Keep the firmware ID and parameter names stable so the records still match.

Firmware ids past the parameters

A firmware can answer more live ids, starting from GP5_NPARAMS, with fw_param_get / fw_param_set: commands or states that aren’t settings. Dreamcatcher does this for its own preset commands. The platform passes it every id it doesn’t own.

Trying it

python3 tools/run_effect.py tremolo x out.wav --tone --set Rate=800 --set Shape=Square
python3 tools/gp5_link.py params
